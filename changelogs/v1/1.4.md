## 1.4.0 — 2026-07-03

EDL et bail signés ensemble : conditions obligatoires, résiliation, et
fiabilisation des notifications de signature.

### Fonctionnalités

- **Les rappels « à signer » disparaissent après signature** : dès qu'un état
  des lieux ou un bail est signé, les notifications associées du destinataire
  courant sont marquées comme lues (badges + « Messages » nettoyés) — quel que
  soit le profil.
  - Signature de l'EDL par le locataire (`locataireAccepter`) → efface les
    notifications `edl_a_signer` de cet EDL.
  - Signature du bail par l'une ou l'autre partie (`setBailSignature`) → efface
    les notifications `bail_garant_requis` / `bail_remplissage`.
  - Nouveau `NotificationsDatasource.markReadForEdl(edlId, {types})`, restreint
    par RLS (`recipient_id = auth.uid()`) : chaque partie n'efface que ses
    propres avis.
- **Onglet « Bail » dans l'EDL individuel** (propriétaire) : configuration du
  **préavis** (défaut légal 1 mois meublé / 3 vide, surchargeable) et
  **résiliation du bail** (« Rompre le bail ») avec date de congé + motif →
  calcul de la **fin effective** (congé + préavis) et retrait automatique des
  échéances de loyer au-delà. Puisque bail et EDL partagent la même signature,
  ces réglages vivent dans l'EDL.
- **Conditions obligatoires pour signer/finaliser l'EDL individuel** : le bail
  et l'EDL étant signés ensemble, l'EDL regroupe les champs requis avant
  finalisation, avec **indicateur « Obligatoire »** (astérisque rouge / coche
  verte) et **pastille par onglet** comptant les champs manquants :
  - **Fenêtre d'avenant** choisie *dans l'EDL* (7/15/30/60/90 j ou « Sans
    avenant »), **rien de présélectionné** — remplace le réglage global de la
    Vision générale ; le choix par EDL est conservé à la finalisation.
  - **Bail avec / sans garant**, puis onglet **« Garant »** : rattacher un ou
    plusieurs **garants actifs** du locataire (bouton retirer). Obligatoire si
    « avec garant ». Les garants rattachés ici sont ceux repris dans le bail.
  - **Mode de règlement de la caution** (Chèque → banque/n°/titulaire ;
    Virement SEPA ; Espèces ; Wero/PayPal).
  - **Signature** ajoutée depuis l'onglet Bail (reprise auto de la signature
    enregistrée au profil si elle existe).
  - **La finalisation est bloquée** tant qu'un champ obligatoire manque (message
    + ouverture de l'onglet concerné).
- Le **card global « Nombre jours avenant »** de la Vision générale est retiré
  (la fenêtre est désormais choisie par EDL).
- **Bail location** (`EdlCollectifNonMeubleePage`) : section « Configuration du
  bail » (fenêtre d'avenant + mode de caution, obligatoires) + verrou de
  finalisation.
- **PDF du bail** : préavis de résiliation aligné sur la valeur configurée, bloc
  « Résiliation en cours » (congé + fin effective) si le bail est résilié, mode
  de règlement de la caution dans le dépôt de garantie, et **garants repris
  depuis l'onglet Garant** (rattachement explicite ; repli sur les garants
  actifs du locataire pour les anciens EDL).

### Corrections

- **Recherche de locataires (formulaire d'EDL)** : s'appuyait sur un id de type
  codé en dur (`type_user_id = 1`). Remplacé par une jointure sur
  `User_Types_Reference` (`code = 'locataire'`) — robuste si les ids changent.
- **Le propriétaire n'était pas prévenu quand le locataire signait** : la RPC
  `notify_edl_proprietaire` ne renseignait pas `recipient_id`, et la
  notification dépendait du chemin d'UI. Corrigé : `recipient_id` posé côté
  base, et la notification « État des lieux accepté » (in-app + e-mail) est
  désormais centralisée dans `locataireAccepter` → elle part quel que soit le
  chemin. Comme le bail réutilise la même signature que l'EDL, accepter l'EDL
  signe aussi le bail : une seule notification couvre les deux.

### Base de données

- `search_locataires(text)` redéfinie (`20260703000031_search_locataires_only`,
  appliquée sur Supabase) : jointure `User_Types_Reference` + filtre
  `code = 'locataire'`, garde de sécurité inchangée (authentifié + rôle
  gestionnaire ; execute révoqué de anon/public).
- `notify_edl_proprietaire` renseigne désormais `recipient_id`
  (`20260703000032_notify_edl_proprietaire_set_recipient`, appliquée sur
  Supabase).
- `etat_de_lieux` : colonnes `preavis_mois`, `bail_conge_date`,
  `bail_fin_effective`, `bail_resilie_motif`, `bail_resilie_at`, `caution_mode`,
  `caution_details` (`20260703000033_bail_config_et_resiliation`) + table
  `etat_de_lieux_garants` (garants rattachés à un EDL, RLS via `can_access_edl`)
  et colonnes caution (`20260703000034_edl_readiness_caution_garants`).
  Appliquées sur Supabase.
- Correction d'un compte de test dont le type était mal saisi.

### Notes techniques

- L'exception `FormatException: null` observée dans `realtime_client`
  (`transformers.dart`, `toInt`) lors des changements sur `Notifications` est
  **capturée par la librairie** (retourne `null`) et sans impact : le realtime
  continue de fonctionner. Le débogueur ne fait que s'arrêter dessus s'il est
  réglé sur « toutes les exceptions ».
